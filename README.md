# BKK Condo Price

ทำนายราคาคอนโดในกรุงเทพฯ จากข้อมูลประกาศขายที่ทีมเก็บเองทั้งหมด:
- จัดกลุ่มทำเล 38 โซนด้วย **K-Means** (เทียบกับ **Fuzzy C-Means**)
- ทำนายราคาด้วย **Linear Regression** (โมเดลหลัก) พร้อมข้อมูลตึก: อายุตึก ระยะถึงรถไฟฟ้า จำนวนยูนิต
- เปรียบเทียบกับ **KNN Regression**, **FFBP neural network** และตัวเปรียบเทียบอื่น (การกรองแบบเว็บประกาศ, Random Forest, Gradient Boosting)
- คาดการณ์ราคาไปถึงปี 2036 จากแนวโน้มดัชนีราคาที่อยู่อาศัยกรุงเทพฯ

ทั้งสามโมเดลเขียนเองด้วย NumPy และมีเทสต์ยืนยันว่าให้ผลตรงกับ scikit-learn มีหน้าเว็บให้กรอกข้อมูลห้อง แล้วได้ราคาประเมินออกมา

Mini project วิชา Machine Learning ปี 2569

## ผลลัพธ์โดยสรุป
ความคลาดเคลื่อนเฉลี่ยเป็นเปอร์เซ็นต์ (MAPE) บนชุดทดสอบ ยิ่งน้อยยิ่งดี วัด 2 แบบ:
- **แบ่งแบบสุ่ม:** ห้องในชุดทดสอบอาจอยู่ในตึกเดียวกับห้องในชุดฝึก
- **ตึกที่ไม่เคยเห็น:** ตึกในชุดทดสอบไม่มีในชุดฝึกเลย

| โมเดล | แบ่งแบบสุ่ม | ตึกที่ไม่เคยเห็น |
|---|---|---|
| การกรองแบบเว็บประกาศ: โซน + ห้องนอนเดียวกัน + พื้นที่ ±10% | 28.9% | 35.0% |
| Baseline: ราคากลางต่อ ตร.ม. ของโซน × พื้นที่ | 29.4% | 34.1% |
| Linear Regression (ไม่มีข้อมูลทำเล) | 41.2% | 40.3% |
| Linear Regression + ระดับทำเลจาก K-Means | 29.1% | 28.3% |
| KNN Regression + ระดับทำเลจาก K-Means | 27.6% | 31.1% |
| **Linear Regression + K-Means + ข้อมูลตึก (โมเดลหลักในหน้าเว็บ)** | 21.3% | **23.4%** |
| KNN Regression + K-Means + ข้อมูลตึก | 21.9% | 30.0% |
| FFBP neural network + K-Means + ข้อมูลตึก | 18.6% | 25.5% |
| Linear Regression + Fuzzy C-Means + ข้อมูลตึก | 22.1% | 26.6% |
| Random Forest + ข้อมูลตึก (อ้างอิง) | 18.2% | 25.9% |
| Gradient Boosting + ข้อมูลตึก (อ้างอิง) | 16.8% | 23.3% |
| **Linear Regression + ข้อมูลตึก + ระดับราคาของโครงการ** | **14.9%** | 27.3% |

- การกรองแบบเว็บประกาศหาห้องเทียบเจอ 93% (แบ่งสุ่ม) และ 89% (ตึกที่ไม่เคยเห็น) ห้องที่หาไม่เจอใช้ราคากลางของโซนแทน
- ข้อมูลตึกลดความคลาดเคลื่อนของ LR บนตึกที่ไม่เคยเห็นจาก 28.3% เหลือ 23.4% ตามค่าสัมประสิทธิ์ ไกลรถไฟฟ้าเพิ่ม 1 กม. ราคาลด 6.7% และตึกเก่าขึ้น 1 ปี ราคาลด 2.8%
- **FFBP** (เขียนตามแบบไฟล์ `FFBP.py` ของวิชา, [src/models/ffbp.py](src/models/ffbp.py)): hidden layer sigmoid 1 ชั้น output เป็นเส้นตรงเพราะทำนายราคา เลือกขนาด hidden และจำนวน epoch ด้วย 5-fold CV เดาห้องในตึกที่เคยเห็นได้แม่นกว่า LR แต่บนตึกที่ไม่เคยเห็น LR ยังดีกว่า
- **Fuzzy C-Means** (ตามแบบไฟล์ `FuzzyCmeans.py`, [src/models/fuzzy_cmeans.py](src/models/fuzzy_cmeans.py)): ใช้สถิติโซนชุดเดียวกับ K-Means และ k เท่ากัน (k = 8, m = 2) แต่ให้แต่ละโซนเป็นสมาชิกได้หลายกลุ่ม มี 11 โซนที่ก้ำกึ่ง (สมาชิกกลุ่มหลักไม่ถึง 0.6) เช่น สุขุมวิท-อโศก, สีลม, สาทร การใช้ค่าสมาชิกแบบนุ่มนวลกลับทำให้ LR แย่ลง (29.1% | 30.8%) เทียบกับกลุ่มแบบแข็งจาก K-Means (29.1% | 28.3%) กราฟอยู่ที่ `reports/figures/fuzzy_memberships.png`
- KNN ไม่ได้ประโยชน์จากข้อมูลตึกบนตึกที่ไม่เคยเห็น เพราะทุก feature ถูกนับระยะเท่ากัน feature ที่ไม่สำคัญจึงดึงผลไปด้วย

### เทียบกับงานก่อนหน้า
งานของ มศว (2563) ทำนายราคาต่อ ตร.ม. ระดับโครงการ ได้ relative error 17.53% เราวัดแบบเดียวกัน (ค่ากลางราคาต่อ ตร.ม. ของแต่ละโครงการในชุดทดสอบ):

| โมเดล | แบ่งแบบสุ่ม: error / R² | ตึกที่ไม่เคยเห็น: error / R² |
|---|---|---|
| Linear Regression + ข้อมูลตึก | 22.3% / 0.645 | 23.7% / 0.663 |
| Gradient Boosting + ข้อมูลตึก | 16.6% / 0.799 | 25.0% / 0.521 |
| Linear Regression + ข้อมูลตึก + ระดับราคาโครงการ | 15.5% / 0.850 | 27.1% / 0.585 |

ตัวเลขเทียบกันได้แค่คร่าว ๆ เพราะข้อมูลและวิธีแบ่งต่างกัน งานก่อนหน้าไม่ได้รายงานกรณีตึกที่ไม่เคยเห็น

### คาดการณ์ราคาปีอนาคต
- ใช้ Linear Regression ตัวเดียวกัน ทำนาย log(ดัชนีราคา) จากปี บนดัชนี BIS กรุงเทพฯ 1991-2026 ([src/evaluate/forecast.py](src/evaluate/forecast.py))
- ช่วงข้อมูลที่ใช้หาแนวโน้มเลือกจาก backtest ย้อนหลัง (เริ่มทำนายจากทุกปี 2001-2025) ได้แนวโน้ม 3.3% ต่อปี
- backtest: ทายล่วงหน้า 1 ปีคลาดเคลื่อน 2.1% ล่วงหน้า 10 ปีคลาดเคลื่อน 17.6%
- ราคาปี X = ราคาประเมินวันนี้ × ตัวคูณของปี X เช่นปี 2036 ตัวคูณ 1.38 (ช่วง 1.05-1.81)
- ดัชนีนี้เป็นที่อยู่อาศัยทุกประเภทในกรุงเทพฯ ไม่ใช่เฉพาะคอนโด

ตัวเลขทั้งหมดมาจาก [reports/metrics.json](reports/metrics.json) และกราฟอยู่ใน [reports/figures/](reports/figures/)

### ระยะทางและวิธีโหวต
| โมเดล | วัดระยะ | รวมผล / โหวต | โค้ด |
|---|---|---|---|
| K-Means | Euclidean ยกกำลังสอง (เทียบกับ Manhattan) | จัดแต่ละโซนเข้ากลุ่มที่ศูนย์กลางใกล้สุด แล้วย้ายศูนย์กลางไปที่ค่าเฉลี่ย เริ่มต้นแบบ k-means++ | [src/models/kmeans.py](src/models/kmeans.py) |
| KNN Regression | Euclidean (เทียบกับ Manhattan) บน feature ที่ standardize แล้ว | ถ่วงน้ำหนักตามระยะ 1/ระยะ ของ k=21 ห้องที่ใกล้สุด (เทียบกับโหวตเท่ากัน) | [src/models/knn_regression.py](src/models/knn_regression.py) |
| Fuzzy C-Means | Euclidean | ทุกโซนเป็นสมาชิกทุกกลุ่มด้วยค่า 0-1 (รวมเป็น 1) ตามระยะถึงศูนย์กลาง | [src/models/fuzzy_cmeans.py](src/models/fuzzy_cmeans.py) |
| FFBP | ไม่ใช้ระยะ | ไม่มีการโหวต ปรับน้ำหนัก W0, W1 ด้วย back-propagation | [src/models/ffbp.py](src/models/ffbp.py) |
| Linear Regression | ไม่ใช้ระยะ | ไม่มีการโหวต หาน้ำหนัก W ที่ทำให้ผลรวมความคลาดเคลื่อนยกกำลังสองน้อยสุด | [src/models/linear_regression.py](src/models/linear_regression.py) |

ระยะและวิธีโหวตที่ใช้จริงเลือกจาก 5-fold cross-validation บนชุดฝึก ไม่ได้ใช้ชุดทดสอบเลือก

ผลการทดลองบนชุดทดสอบแบบแบ่งสุ่ม (MAPE):

| KNN | โหวตเท่ากัน | ถ่วงน้ำหนักตามระยะ |
|---|---|---|
| Euclidean | 28.1% (k=8) | 27.6% (k=21) |
| Manhattan | 27.8% (k=9) | 27.9% (k=27) |

| K-Means | CV MAPE ของ LR | silhouette |
|---|---|---|
| Euclidean (k=8) | 28.7% | 0.391 |
| Manhattan (k=7) | 29.4% | 0.376 |

**สรุป:** การเลือกระยะทางและวิธีโหวตมีผลน้อยมาก ต่างกันไม่เกิน 0.5 จุดใน KNN สิ่งที่มีผลมากกว่าคือข้อมูลทำเล (จาก K-Means) และระดับราคาของโครงการ

โค้ดโมเดลทั้งสามเขียนตามแบบโค้ดตัวอย่างของวิชา (ตัวแปร `X, C, D, idx, K, W`) และเพิ่ม k-means++ สำหรับเลือกศูนย์กลางเริ่มต้น เพราะการสุ่มจุดเริ่มต้นตรง ๆ ทำให้ความคลาดเคลื่อนของ LR สูงขึ้นจาก 29.1% เป็น 30.2% และจาก 28.3% เป็น 31.7% (ตึกที่ไม่เคยเห็น)

**ข้อควรระวัง:** ในการแบ่งแบบสุ่ม ห้องในชุดทดสอบ 36.6% มีห้องที่เกือบเหมือนกันอยู่ในชุดฝึก (โครงการเดียวกัน จำนวนห้องนอนเท่ากัน พื้นที่ใกล้กัน) ตัวเลขของโมเดลที่ใช้ระดับราคาโครงการจึงอาจดีเกินจริง ให้ใช้คอลัมน์ "ตึกที่ไม่เคยเห็น" เป็นกรณีที่เข้มงวดที่สุด

## วิธีติดตั้ง
ต้องมี Python 3.14 (ทดสอบบน macOS)

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

## วิธีรัน

**เปิดหน้าเว็บ** (ใช้โมเดลที่ฝึกไว้แล้วใน `models/model_bundle.pkl`):
```bash
.venv/bin/streamlit run app/streamlit_app.py
```
แล้วเปิด http://localhost:8501

**ขึ้นเว็บออนไลน์ (Live demo):** ทำตามขั้นตอนใน [docs/deploy.md](docs/deploy.md) ด้วย Streamlit Community Cloud

**ฝึกและประเมินโมเดลใหม่** จากข้อมูลที่ทำความสะอาดแล้ว:
```bash
.venv/bin/python -m src.evaluate.run
.venv/bin/python -m src.evaluate.led_compare
.venv/bin/python -m src.evaluate.forecast
```

**รันเทสต์** (โมเดลที่เขียนเองต้องให้ผลตรงกับ scikit-learn):
```bash
.venv/bin/python -m pytest tests
```

**สร้างข้อมูลใหม่ทั้งหมดจาก HTML ดิบ** (ต้องมีไฟล์ใน `data/raw/`):
```bash

.venv/bin/python scripts/parse_led.py
.venv/bin/python scripts/parse_projects.py
```

## ลำดับการทำงานของ pipeline
1. **แยกข้อมูล** (`scripts/parse_raw.py`): อ่านการ์ดประกาศจาก HTML ที่บันทึกไว้ ระบุโซนและหน้าจาก URL ที่ Chrome ฝังในไฟล์ แต่ละฟิลด์ (ห้องนอน ห้องน้ำ ชั้น พื้นที่) ระบุจากรูปร่างไอคอน เพราะเว็บไม่มีข้อความกำกับ
2. **ใส่ label และทำความสะอาด** (`src/clean/clean.py`): ใส่เขตจากตารางที่ทำเอง ประเภทห้อง และห้องมือ 1 ตัดประกาศซ้ำ ประกาศขายดาวน์ ค่าที่ผิดปกติ (ตัดราย IQR แยกตามโซน) บันทึกจำนวนแถวที่ตัดในแต่ละกฎไว้ใน `reports/cleaning_log.json`
3. **จัดกลุ่มทำเล** (`src/features/build.py`): K-Means จัดกลุ่ม 38 โซนจากราคากลางต่อ ตร.ม., พื้นที่กลาง และสัดส่วนห้องมือ 1 (คำนวณจากชุดฝึกเท่านั้น) เลือกจำนวนกลุ่ม k และระยะ (Euclidean / Manhattan) จาก cross-validation ของ Linear Regression ได้ k = 8 แบบ Euclidean และบันทึก silhouette ของทุก k ไว้ด้วย
4. **ข้อมูลตึก** (`scripts/parse_projects.py`, `src/features/build.py`): อ่านข้อมูลโครงการที่ฝังในหน้าประกาศ (ปีที่สร้างเสร็จ จำนวนยูนิต ชั้น สิ่งอำนวยความสะดวก ระยะถึงรถไฟฟ้าและห้าง) แล้วจับคู่กับประกาศด้วยชื่อโครงการ ประกาศที่ไม่มีข้อมูลตึกใช้ค่ากลางจากชุดฝึก
5. **ฝึกและประเมิน** (`src/evaluate/run.py`):
   - Linear Regression ทำนาย log(ราคา)
   - KNN เลือกระยะ วิธีโหวต และจำนวนเพื่อนบ้าน k ด้วย 5-fold cross-validation
   - การกรองแบบเว็บประกาศ, Random Forest และ Gradient Boosting ของ scikit-learn ใช้เป็นตัวเปรียบเทียบ
   - ประเมินทั้ง 2 แบบการแบ่งข้อมูล
6. **หน้าเว็บ** (`app/streamlit_app.py`):
   - กรอกโซน พื้นที่ ห้องนอน ห้องน้ำ ชั้น และโครงการ (ไม่บังคับ) ถ้าเลือกโครงการ ระบบใช้ข้อมูลตึกของโครงการให้ ถ้าไม่เลือก ให้กรอกปีที่สร้างเสร็จและระยะถึงรถไฟฟ้าเอง
   - แสดงราคาจาก LR + ข้อมูลตึก และ KNN พร้อมช่วงราคา ระดับทำเล และ 5 ห้องที่คล้ายที่สุดในข้อมูล
   - เลือกปี 2026-2036 เพื่อดูราคาคาดการณ์ตามแนวโน้มตลาด
   - ธีมตาม design system ดำ-ทองที่ทีมเลือก

```
│   ├── labeled/            ข้อมูลหลังใส่ label

│   ├── clean/              ใส่ label และทำความสะอาด
```

## ข้อจำกัด
- ใช้ราคาประกาศขาย ไม่ใช่ราคาซื้อขายจริง
- ข้อมูลประกาศเก็บครั้งเดียว ราคาปีอนาคตจึงใช้แนวโน้มดัชนีราคาทั้งตลาด ไม่ใช่แนวโน้มของแต่ละโซน
- เขตที่ใช้ใน K-Means เป็น label ระดับโซน ไม่ใช่ระดับตึก
- ระยะถึงรถไฟฟ้าและห้างมาจากรายการสถานที่ใกล้เคียงของเว็บ (รัศมีประมาณ 3 กม.) ถ้าไม่มีในรายการ ถือว่าไกลเกิน 3 กม.
- ประกาศ 2.5% ไม่มีข้อมูลตึก ค่าสัมประสิทธิ์ของตัวบอก "มีข้อมูลตึก" จึงไม่เสถียร
