# BKK Condo Price

ทำนายราคาคอนโดในกรุงเทพฯ จากข้อมูลประกาศขายที่ทีมเก็บเองทั้งหมด:
- จัดกลุ่มทำเล 38 โซนด้วย **K-Means** (เทียบกับ **Fuzzy C-Means**)
- ทำนายราคาด้วย **Linear Regression** (โมเดลหลัก) พร้อมข้อมูลตึก: อายุตึก ระยะถึงรถไฟฟ้า จำนวนยูนิต
- เปรียบเทียบกับ **KNN Regression**, **FFBP neural network** และตัวเปรียบเทียบอื่น (การกรองแบบเว็บประกาศ, Random Forest, Gradient Boosting)
- คาดการณ์ราคาไปถึงปี 2036 จากแนวโน้มดัชนีราคาที่อยู่อาศัยกรุงเทพฯ

ทั้งห้าโมเดลหลัก (K-Means, Fuzzy C-Means, Linear Regression, KNN, FFBP) เขียนเองด้วย NumPy และมีเทสต์ยืนยันว่าให้ผลตรงกับ scikit-learn มีหน้าเว็บให้กรอกข้อมูลห้อง แล้วได้ราคาประเมินออกมา

## ผลลัพธ์โดยสรุป
ความคลาดเคลื่อนเฉลี่ยเป็นเปอร์เซ็นต์ (MAPE) บนชุดทดสอบ ยิ่งน้อยยิ่งดี วัด 2 แบบ:
- **แบ่งแบบสุ่ม:** ห้องในชุดทดสอบอาจอยู่ในตึกเดียวกับห้องในชุดฝึก
- **ตึกที่ไม่เคยเห็น:** ตึกในชุดทดสอบไม่มีในชุดฝึกเลย

| โมเดล | แบ่งแบบสุ่ม | ตึกที่ไม่เคยเห็น |
|---|---|---|
| การกรองแบบเว็บประกาศ: โซน + ห้องนอนเดียวกัน + พื้นที่ ±10% | 28.9% | 35.0% |
| Baseline: ราคากลางต่อ ตร.ม. ของโซน × พื้นที่ | 29.4% | 34.1% |
| Linear Regression (ไม่มีข้อมูลทำเล) | 41.2% | 40.3% |
| Linear Regression + ระดับทำเลจาก K-Means | 29.1% | 30.1% |
| KNN Regression + ระดับทำเลจาก K-Means | 27.6% | 33.6% |
| Linear Regression + K-Means + ข้อมูลตึก | 21.3% | 24.0% |
| KNN Regression + K-Means + ข้อมูลตึก | 21.9% | 31.0% |
| FFBP neural network + K-Means + ข้อมูลตึก | 18.6% | 24.9% |
| Linear Regression + Fuzzy C-Means + ข้อมูลตึก | 22.1% | 26.4% |
| Random Forest + ข้อมูลตึก (อ้างอิง) | 18.2% | 27.8% |
| Gradient Boosting + ข้อมูลตึก (อ้างอิง) | 16.8% | 24.8% |
| Linear Regression + ข้อมูลตึก + ราคาย่านใกล้เคียง (IDW) | 19.9% | 21.3% |
| เฉลี่ย Linear Regression + Gradient Boosting (ข้อมูลตึก + ราคาย่าน IDW) | 16.0% | 20.4% |
| **Linear Regression + ข้อมูลตึกละเอียด + ราคาย่าน IDW หลายสเกล (NumPy ล้วน)** | 18.4% | **18.6%** |
| Gradient Boosting (`log ราคา/ตร.ม.`) + ข้อมูลตึกละเอียด + IDW (อ้างอิง) | 14.8% | 20.5% |
| Random Forest (`log ราคา/ตร.ม.`) + ข้อมูลตึกละเอียด + IDW (อ้างอิง) | **13.3%** | 21.1% |
| **เฉลี่ย LR + GB (ข้อมูลตึกละเอียด + IDW, ถ่วงน้ำหนักด้วย GroupCV)** (หน้าเว็บ: ตึกที่ไม่มีประกาศอื่น) | 14.8% | **18.9%** |
| **Linear Regression + ข้อมูลตึก + ระดับราคาของโครงการ** (หน้าเว็บ: ตึกที่มีประกาศอื่น) | 14.9% | 27.4% |
| Linear Regression + ข้อมูลตึกละเอียด + ระดับราคาของโครงการ | 14.5% | 24.9% |

- การกรองแบบเว็บประกาศหาห้องเทียบเจอ 93% (แบ่งสุ่ม) และ 89% (ตึกที่ไม่เคยเห็น) ห้องที่หาไม่เจอใช้ราคากลางของโซนแทน
- ข้อมูลตึกลดความคลาดเคลื่อนของ LR บนตึกที่ไม่เคยเห็นจาก 28.3% เหลือ 23.4% ตามค่าสัมประสิทธิ์ ไกลรถไฟฟ้าเพิ่ม 1 กม. ราคาลด 6.7% และตึกเก่าขึ้น 1 ปี ราคาลด 2.8%
- **FFBP** (เขียนตามแบบไฟล์ `FFBP.py` ของวิชา, [src/models/ffbp.py](src/models/ffbp.py)): hidden layer sigmoid 1 ชั้น output เป็นเส้นตรงเพราะทำนายราคา เลือกขนาด hidden และจำนวน epoch ด้วย 5-fold CV เดาห้องในตึกที่เคยเห็นได้แม่นกว่า LR แต่บนตึกที่ไม่เคยเห็น LR ยังดีกว่า
- **Fuzzy C-Means** (ตามแบบไฟล์ `FuzzyCmeans.py`, [src/models/fuzzy_cmeans.py](src/models/fuzzy_cmeans.py)): ใช้สถิติโซนชุดเดียวกับ K-Means และ k เท่ากัน (k = 8, m = 2) แต่ให้แต่ละโซนเป็นสมาชิกได้หลายกลุ่ม มี 11 โซนที่ก้ำกึ่ง (สมาชิกกลุ่มหลักไม่ถึง 0.6) เช่น สุขุมวิท-อโศก, สีลม, สาทร การใช้ค่าสมาชิกแบบนุ่มนวลกลับทำให้ LR แย่ลง (29.1% | 30.8%) เทียบกับกลุ่มแบบแข็งจาก K-Means (29.1% | 28.3%) กราฟอยู่ที่ `reports/figures/fuzzy_memberships.png`
- **ราคาย่านใกล้เคียงแบบถ่วงน้ำหนักระยะ (IDW)** ([src/features/build.py](src/features/build.py) `NeighbourhoodPrice`, `MultiScaleNeighbourhood`): กรองพิกัดนอกกรุงเทพฯ ก่อนคำนวณระยะ แล้วเฉลี่ยราคาต่อ ตร.ม. ของตึกอื่นที่ใกล้ที่สุดแบบถ่วงน้ำหนัก $1/(d+0.25\text{ กม.})$ ทั้งระดับซอย (5 ตึก) และระดับย่าน (20 ตึก) พร้อมส่วนต่างอายุตึกเทียบเพื่อนบ้าน โดยไม่นับตึกของห้องนั้นเอง และสร้างตารางใหม่ภายในทุก fold ของ CV (ใช้ `GroupKFold` สำหรับกรณีตึกที่ไม่เคยเห็น) เพื่อกัน data leakage
- **ข้อมูลตึกละเอียด + Target `log(ราคา/ตร.ม.)`:** ดึงฟีเจอร์ที่แยกไว้แล้วใน `projects.csv` มาใช้เพิ่ม ได้แก่ ความหนาแน่นยูนิตต่อชั้น (`units_per_floor_log`), ตึกสูง > 8 ชั้น (`is_high_rise`), สัดส่วนชั้น (`floor_ratio`), พื้นที่ต่อห้อง (`area_per_room_log`), ระยะห่าง CBD (`log_cbd_km`), สายรถไฟฟ้า (`is_bts`, `is_mrt`), ระยะโรงพยาบาล และสิ่งอำนวยความสะดวกพื้นฐาน (สระ/ฟิตเนส/ที่จอดรถ) ลดความคลาดเคลื่อนของ **Linear Regression (NumPy ล้วน)** บนตึกที่ไม่เคยเห็นจาก 23.4% เหลือ **18.6%** ($R^2 = 0.847$, MAE 1.31 ล้านบาท)
- **การเฉลี่ย 2 โมเดล (CV-weighted):** รวมราคาจาก LR และ Gradient Boosting (ทำนาย `log ราคา/ตร.ม.` แล้วคูณพื้นที่กลับ) โดยหาค่าน้ำหนักด้วย GroupCV ได้ MAPE **18.9%** (ใกล้ ±20% ได้ **66.8%**, ช่วง >15 ล้านเพิ่มจาก 47% เป็น **53%**) บนตึกที่ไม่เคยเห็น และ **14.8%** (ใกล้ ±20% ได้ **78.3%**) บนชุดแบ่งแบบสุ่ม
- ความคลาดเคลื่อนแยกรายโซนอยู่ใน `reports/zone_errors_random_split.csv` และ `reports/zone_errors_project_split.csv` และแยกตามช่วงราคาอยู่ใน `reports/price_band_errors_project_level.csv` และ `reports/price_band_errors_blend_unseen.csv`
- **โมเดลที่หน้าเว็บใช้:** ถ้าตึกที่เลือกมีประกาศห้องอื่นในข้อมูล ใช้ LR + ระดับราคาของโครงการ วัดเฉพาะห้องทดสอบแบบนี้ (570 ห้อง) คลาดเฉลี่ย **13.1%** และใกล้ ±20% ได้ **81.2%** กรณีอื่นถือเป็นตึกที่ไม่เคยเห็น ใช้การเฉลี่ย LR + GB แบบข้อมูลตึกละเอียด + IDW (**66.8%**, คลาดเฉลี่ย **18.9%**) พร้อมปรับโซนอัตโนมัติเมื่อเลือกโซนไม่ตรงกับโครงการ และเตือนกรณีห้องสิทธิการเช่า (Leasehold) ในย่านวิทยุ-เพลินจิต-หลังสวน
- KNN ไม่ได้ประโยชน์จากข้อมูลตึกบนตึกที่ไม่เคยเห็น เพราะทุก feature ถูกนับระยะเท่ากัน feature ที่ไม่สำคัญจึงดึงผลไปด้วย

### วัดผลแบบไม่อวยตัวเอง (`src/evaluate/benchmark.py`)
ชุดทดสอบ seed 42 ด้านบนถูกดูซ้ำระหว่างเลือกโมเดล ตัวเลขจึงอาจดีเกินจริง ตั้งแต่นี้การเลือกโมเดลใช้ benchmark นี้แทน:
- ล็อก holdout ไว้ก่อน: ตึก 15% (กรณีตึกใหม่) และห้อง 10% ของตึกอื่น (กรณีตึกที่รู้จัก) เลือกด้วย hash ของชื่อตึก/เลขประกาศ ทำความสะอาดข้อมูลเพิ่มทีหลังก็ไม่ทำให้ holdout สลับ ใช้วัดครั้งเดียวตอนท้ายด้วย `--final` ห้ามใช้เลือกโมเดล
- ข้อมูลส่วนที่เหลือวัดด้วย grouped 5-fold CV ซ้ำ 3 seed กรณีตึกใหม่จัดกลุ่มตามตึก กรณีตึกที่รู้จักจัดกลุ่มประกาศซ้ำไว้ใน fold เดียวกัน
- ทุกโมเดลต้องชนะ baseline ง่าย ๆ: ตึกใหม่เทียบกับราคากลางโซน × พื้นที่ ตึกที่รู้จักเทียบกับราคาต่อ ตร.ม. เฉลี่ยของห้องอื่นในตึกเดียวกัน × พื้นที่ (ใช้ประวัติชุดเดียวกับโมเดล)

**การทำความสะอาดที่เพิ่ม** (`src/clean/clean.py`, จำนวนใน `reports/cleaning_log.json`):
- ชื่อโครงการที่เป็นชื่อโซน เช่น "มีนบุรี-ร่มเกล้า" 81 แถว: ล้างชื่อออก (เก็บแถวไว้) ไม่ให้ห้องคนละตึกถูกนับเป็นตึกเดียว
- ห้องเดียวกันที่ลงประกาศซ้ำ (ตึก ชั้น ห้องนอนเดียวกัน พื้นที่ต่าง ≤ 1 ตร.ม. ราคาต่าง ≤ 3%): ตัด 266 แถว ข้อมูลสะอาดเหลือ 4,668 แถว

**โมเดลตึกที่รู้จัก** (`KnownBuildingPrice` ใน `src/features/build.py`):
1. ระดับราคาของตึก = ครึ่งหนึ่ง mean ครึ่งหนึ่ง median ของ log ราคาต่อ ตร.ม. ห้องอื่นในตึก ห้องที่ราคาต่อ ตร.ม. ห่างจากห้องอื่นในตึกเกิน 1.8 เท่า (ตึกที่มี 3 ห้องขึ้นไป) ไม่นำมาคิด
2. Bayesian shrinkage: (n × ระดับตึก + m × ราคาจากโมเดลตึกใหม่) / (n + m), m = 0.5 เลือกด้วย grouped CV จาก 0.25/0.5/1/2 ตึกที่มีประกาศน้อยจึงถูกดึงเข้าหาราคาย่านมากกว่า
3. ปรับตามชั้นและขนาดห้องเทียบกับห้องอื่นในตึกด้วย Linear Regression (สูงขึ้น 1 ชั้น ราคาต่อ ตร.ม. ขึ้นประมาณ 0.2%)
4. ประกาศจากหน้าเกิน 2 ของโซนสุขุมวิทและสีลม (1,388 แถวที่ใช้ได้) ใช้เป็นประวัติราคาของตึกตัวเองเท่านั้น ไม่เข้าสถิติระดับโซนและโมเดลตึกใหม่ จึงไม่ทำให้โซนเอียง (ผล CV: แทบไม่เปลี่ยนความแม่น แต่ทำให้รู้จักตึกมากขึ้น)

ผลของโมเดลที่หน้าเว็บใช้อยู่ (เฉลี่ย 3 seed, `reports/benchmark.json`):

| กรณี | โมเดล | MAPE | ใกล้ ±20% | baseline MAPE | ห้อง > 120 ตร.ม. ใกล้ ±20% | โซนที่ทายเอียงที่สุด |
|---|---|---|---|---|---|---|
| ตึกใหม่ | เฉลี่ย LR + GB (ข้อมูลตึกละเอียด + IDW) | 18.6% (±0.3) | 64.6% | 32.1% | 44.6% | 16.8% |
| ตึกที่รู้จัก | ราคาตึก + shrinkage + ปรับชั้น/ขนาด | **11.8%** (±0.0) *(เดิม 13.1%)* | **82.7%** *(เดิม 80.1%)* | 12.7% | 72.4% | 3.0% |

กรณีตึกใหม่ไม่ได้แก้ใน PR นี้ ตัวเลขต่างจากเดิม (18.1%) เพราะ (1) holdout ใหม่แบบ hash ได้ตึกชุด development ต่างไป: ข้อมูลเดิมบนการแบ่งใหม่ได้ 18.45% และ (2) ข้อมูลที่ตัดประกาศซ้ำแล้ว ไม่ใช่ชุดแถวเดียวกันจึงเทียบตรง ๆ ไม่ได้

`tests/test_accuracy.py`: leakage, sanity และเกณฑ์ของกรณีตึกที่รู้จักผ่านทั้งหมด ยังไม่ผ่าน 4 ข้อซึ่งเป็นกรณีตึกใหม่ทั้งหมด (MAPE ≤ 18%, ใกล้ ±20% ≥ 67%, ห้องใหญ่ ≥ 62%, โซนเอียง ≤ 15%) เกณฑ์ไม่ถูกลดลง

### เทียบกับงานก่อนหน้า

| โมเดล | แบ่งแบบสุ่ม: error / R² | ตึกที่ไม่เคยเห็น: error / R² |
|---|---|---|
| Linear Regression + ข้อมูลตึก | 22.3% / 0.645 | 24.3% / 0.686 |
| Linear Regression + ข้อมูลตึกละเอียด + IDW (NumPy ล้วน) | 18.8% / 0.742 | **19.2% / 0.677** |
| เฉลี่ย LR + GB (ข้อมูลตึกละเอียด + IDW) | **14.9% / 0.785** | 20.1% / 0.635 |
| Random Forest (`log ราคา/ตร.ม.`) + ข้อมูลตึกละเอียด + IDW | **13.7% / 0.858** | 22.8% / 0.606 |
| Linear Regression + ข้อมูลตึก + ระดับราคาโครงการ | 15.5% / 0.850 | 27.1% / 0.601 |

ตัวเลขเทียบกันได้แค่คร่าว ๆ เพราะข้อมูลและวิธีแบ่งต่างกัน งานก่อนหน้าไม่ได้รายงานกรณีตึกที่ไม่เคยเห็น

### คาดการณ์ราคาปีอนาคต
- ใช้ Linear Regression ตัวเดียวกัน ทำนาย log(ดัชนีราคา) จากปี บนดัชนี BIS กรุงเทพฯ 1991-2026 ([src/evaluate/forecast.py](src/evaluate/forecast.py))
- ช่วงข้อมูลที่ใช้หาแนวโน้มเลือกจาก backtest ย้อนหลัง (เริ่มทำนายจากทุกปี 2001-2025) ได้แนวโน้ม 3.3% ต่อปี
- backtest: ทายล่วงหน้า 1 ปีคลาดเคลื่อน 2.1% ล่วงหน้า 10 ปีคลาดเคลื่อน 17.6%
- ราคาปี X = ราคาประเมินวันนี้ × ตัวคูณของปี X เช่นปี 2036 ตัวคูณ 1.38 (ช่วง 1.05-1.81)
- ดัชนีนี้เป็นที่อยู่อาศัยทุกประเภทในกรุงเทพฯ ไม่ใช่เฉพาะคอนโด

ตัวเลขทั้งหมดมาจาก [reports/metrics.json](reports/metrics.json) และกราฟอยู่ใน [reports/figures/](reports/figures/)

### ระยะทางและวิธีโหวต
| โมเดล | วัดระยะ | รวมผล / โหวต | โค้ด |
|---|---|---|---|
| K-Means | Euclidean ยกกำลังสอง (เทียบกับ Manhattan) | จัดแต่ละโซนเข้ากลุ่มที่ศูนย์กลางใกล้สุด แล้วย้ายศูนย์กลางไปที่ค่าเฉลี่ย เริ่มต้นแบบ k-means++ | [src/models/kmeans.py](src/models/kmeans.py) |
| KNN Regression | Euclidean (เทียบกับ Manhattan) บน feature ที่ standardize แล้ว | ถ่วงน้ำหนักตามระยะ 1/ระยะ ของ k=21 ห้องที่ใกล้สุด (เทียบกับโหวตเท่ากัน) | [src/models/knn_regression.py](src/models/knn_regression.py) |
| Fuzzy C-Means | Euclidean | ทุกโซนเป็นสมาชิกทุกกลุ่มด้วยค่า 0-1 (รวมเป็น 1) ตามระยะถึงศูนย์กลาง | [src/models/fuzzy_cmeans.py](src/models/fuzzy_cmeans.py) |
| FFBP | ไม่ใช้ระยะ | ไม่มีการโหวต ปรับน้ำหนัก W0, W1 ด้วย back-propagation | [src/models/ffbp.py](src/models/ffbp.py) |
| Linear Regression | ไม่ใช้ระยะ | ไม่มีการโหวต หาน้ำหนัก W ที่ทำให้ผลรวมความคลาดเคลื่อนยกกำลังสองน้อยสุด | [src/models/linear_regression.py](src/models/linear_regression.py) |

ระยะและวิธีโหวตที่ใช้จริงเลือกจาก 5-fold cross-validation บนชุดฝึก ไม่ได้ใช้ชุดทดสอบเลือก

ผลการทดลองบนชุดทดสอบแบบแบ่งสุ่ม (MAPE):

| KNN | โหวตเท่ากัน | ถ่วงน้ำหนักตามระยะ |
|---|---|---|
| Euclidean | 28.1% (k=8) | 27.6% (k=21) |
| Manhattan | 27.8% (k=9) | 27.9% (k=27) |

| K-Means | CV MAPE ของ LR | silhouette |
|---|---|---|
| Euclidean (k=8) | 28.7% | 0.391 |
| Manhattan (k=7) | 29.4% | 0.376 |

**สรุป:** การเลือกระยะทางและวิธีโหวตมีผลน้อยมาก ต่างกันไม่เกิน 0.5 จุดใน KNN สิ่งที่มีผลมากกว่าคือข้อมูลทำเล (จาก K-Means) และระดับราคาของโครงการ

โค้ดโมเดลทั้งสามเขียนตามแบบโค้ดตัวอย่างของวิชา (ตัวแปร `X, C, D, idx, K, W`) และเพิ่ม k-means++ สำหรับเลือกศูนย์กลางเริ่มต้น เพราะการสุ่มจุดเริ่มต้นตรง ๆ ทำให้ความคลาดเคลื่อนของ LR สูงขึ้นจาก 29.1% เป็น 30.2% และจาก 28.3% เป็น 31.7% (ตึกที่ไม่เคยเห็น)

**ข้อควรระวัง:** ในการแบ่งแบบสุ่ม ห้องในชุดทดสอบ 36.6% มีห้องที่เกือบเหมือนกันอยู่ในชุดฝึก (โครงการเดียวกัน จำนวนห้องนอนเท่ากัน พื้นที่ใกล้กัน) ตัวเลขของโมเดลที่ใช้ระดับราคาโครงการจึงอาจดีเกินจริง ให้ใช้คอลัมน์ "ตึกที่ไม่เคยเห็น" เป็นกรณีที่เข้มงวดที่สุด

## ลำดับการทำงานของ pipeline
1. **แยกข้อมูล** (`scripts/parse_raw.py`): อ่านการ์ดประกาศจาก HTML ที่บันทึกไว้ ระบุโซนและหน้าจาก URL ที่ Chrome ฝังในไฟล์ แต่ละฟิลด์ (ห้องนอน ห้องน้ำ ชั้น พื้นที่) ระบุจากรูปร่างไอคอน เพราะเว็บไม่มีข้อความกำกับ
2. **ใส่ label และทำความสะอาด** (`src/clean/clean.py`): ใส่เขตจากตารางที่ทำเอง ประเภทห้อง และห้องมือ 1 ตัดประกาศซ้ำ ประกาศขายดาวน์ ค่าที่ผิดปกติ (ตัดราย IQR แยกตามโซน) บันทึกจำนวนแถวที่ตัดในแต่ละกฎไว้ใน `reports/cleaning_log.json`
3. **จัดกลุ่มทำเล** (`src/features/build.py`): K-Means จัดกลุ่ม 38 โซนจากราคากลางต่อ ตร.ม., พื้นที่กลาง และสัดส่วนห้องมือ 1 (คำนวณจากชุดฝึกเท่านั้น) เลือกจำนวนกลุ่ม k และระยะ (Euclidean / Manhattan) จาก cross-validation ของ Linear Regression ได้ k = 8 แบบ Euclidean และบันทึก silhouette ของทุก k ไว้ด้วย
4. **ข้อมูลตึก** (`scripts/parse_projects.py`, `src/features/build.py`): อ่านข้อมูลโครงการที่ฝังในหน้าประกาศ (ปีที่สร้างเสร็จ จำนวนยูนิต ชั้น สิ่งอำนวยความสะดวก ระยะถึงรถไฟฟ้าและห้าง) แล้วจับคู่กับประกาศด้วยชื่อโครงการ ประกาศที่ไม่มีข้อมูลตึกใช้ค่ากลางจากชุดฝึก
5. **ฝึกและประเมิน** (`src/evaluate/run.py`):
   - Linear Regression ทำนาย log(ราคา)
   - KNN เลือกระยะ วิธีโหวต และจำนวนเพื่อนบ้าน k ด้วย 5-fold cross-validation
   - การกรองแบบเว็บประกาศ, Random Forest และ Gradient Boosting ของ scikit-learn ใช้เป็นตัวเปรียบเทียบ
   - ประเมินทั้ง 2 แบบการแบ่งข้อมูล
6. **หน้าเว็บ** (`app/streamlit_app.py`):
   - กรอกโซน พื้นที่ ห้องนอน ห้องน้ำ ชั้น และโครงการ (ไม่บังคับ) ถ้าเลือกโครงการ ระบบใช้ข้อมูลตึกของโครงการให้ ถ้าไม่เลือก ให้กรอกปีที่สร้างเสร็จและระยะถึงรถไฟฟ้าเอง
   - ราคาหลัก: ตึกที่มีประกาศห้องอื่นในข้อมูลใช้ LR + ระดับราคาของโครงการ ตึกอื่นใช้การเฉลี่ย LR + Gradient Boosting พร้อมราคาย่านใกล้เคียง ถ้าไม่ระบุโครงการ ระบบไม่รู้พิกัดตึก จึงใช้ราคากลางของโซนแทน
   - กล่อง "ราคานี้เชื่อได้แค่ไหน" บอกผลทดสอบเป็นภาษาคนทั่วไป เช่น "ไม่เกิน 20% ได้ 6.5 ใน 10 ห้อง" ทั้งภาพรวม ช่วงราคาเดียวกัน และโซนเดียวกัน (โซนที่มีห้องทดสอบไม่ถึง 10 ห้องไม่บอก)
   - เตือนเมื่อข้อมูลขัดกัน เช่น ห้องมือ 1 ในตึกที่สร้างเสร็จนานแล้ว หรือเมื่อผลตกช่วงราคาหรือโซนที่ทายพลาดบ่อย
   - แสดงราคาจากแต่ละโมเดล ราคา KNN ระดับทำเล และ 5 ห้องที่คล้ายที่สุดในข้อมูล
   - เลือกปี 2026-2036 เพื่อดูราคาคาดการณ์ตามแนวโน้มตลาด
   - ธีมตาม design system ดำ-ทองที่ทีมเลือก

## ข้อจำกัด
- ใช้ราคาประกาศขาย ไม่ใช่ราคาซื้อขายจริง
- ข้อมูลประกาศเก็บครั้งเดียว ราคาปีอนาคตจึงใช้แนวโน้มดัชนีราคาทั้งตลาด ไม่ใช่แนวโน้มของแต่ละโซน
- เขตที่ใช้ใน K-Means เป็น label ระดับโซน ไม่ใช่ระดับตึก
- ระยะถึงรถไฟฟ้าและห้างมาจากรายการสถานที่ใกล้เคียงของเว็บ (รัศมีประมาณ 3 กม.) ถ้าไม่มีในรายการ ถือว่าไกลเกิน 3 กม.
- **ไม่แยกกรรมสิทธิ์ Freehold / Leasehold:** คอนโดสิทธิการเช่า 30 ปี (เช่น ย่านหลังสวน/ราชดำริ) มีราคาต่ำกว่าแบบขายขาดข้างเคียง 30–50% จึงเป็นแหล่งความคลาดเคลื่อนหลักของช่วงราคา > 15 ล้านบาท หน้าเว็บมีคำเตือนเพิ่มเติมในโซนดังกล่าว
- ประกาศ 2.5% ไม่มีข้อมูลตึก ค่าสัมประสิทธิ์ของตัวบอก "มีข้อมูลตึก" จึงไม่เสถียร
